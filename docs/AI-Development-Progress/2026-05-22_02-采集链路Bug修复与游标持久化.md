# 采集链路 Bug 修复与游标持久化 — 2026-05-22 10:43

## 问题描述

用户反馈数据库中无最新数据，需要排查 agent 采集→上报全链路。

## 排查过程

### 1. 端到端运行检测

以 `RUST_LOG=info` 前台运行 agent，发现两个 JSON 解析错误导致大量数据丢弃。

### 2. Session 文件解析失败

Session JSON 的 `startedAt` 字段实际为**数字毫秒时间戳**（如 `1779414618547`），`SessionMeta.started_at` 仅接受 `Option<String>`，导致所有 session 文件解析失败。

### 3. Conversation JSONL 解析失败

Claude Code 工具执行失败时 `toolUseResult` 为**错误字符串**（如 `"Error: Exit code 127"`），`ConversationEvent.tool_use_result` 仅接受 `Option<ToolUseResult>`，导致整条对话事件丢弃。

### 4. 队列积压分析

Trae 采集器游标为内存态，每次重启全量重采 2100+ 事件入队。上报批次仅 50 条/轮，队列快速膨胀至 7000+，当前 Claude 会话数据堵在队尾。

---

## 修复内容

### Bug 1: Session `startedAt` 类型兼容

- **文件**: `agent/src/collector/claude/session.rs`
- **原因**: `startedAt` 为数字时 `serde_json::from_str` 失败
- **修复**: `started_at` 改为 `Option<serde_json::Value>`，`parsed_started_at()` 同时处理 String (ISO 8601) 和 Number (毫秒)

### Bug 2: Conversation `toolUseResult` 类型兼容

- **文件**: `agent/src/collector/claude/conversation.rs` + `mod.rs`
- **原因**: 工具失败时 `toolUseResult` 为错误字符串而非对象
- **修复**: 改为 `Option<serde_json::Value>`，聚合层用 `serde_json::from_value` 转换，非对象则静默跳过

### 改进 3: Trae 游标持久化

- **文件**: `agent/src/collector/trae/collector.rs` + `main.rs`
- **修复**: `TraeCursor` 加 `Serialize/Deserialize`，采集后写入 `trae_cursor.json`，重启自动加载
- **效果**: 重启后 Trae 零重采（2100+ → 0）

### 改进 4: Claude Code 游标持久化

- **文件**: `agent/src/collector/claude/mod.rs` + `main.rs` + `service.rs`
- **修复**: `ClaudeCursor` 加 `Serialize/Deserialize`，采集后写入 `claude_cursor.json`，重启自动加载
- **效果**: 重启后 Claude 增量采集（217 → ~1）
