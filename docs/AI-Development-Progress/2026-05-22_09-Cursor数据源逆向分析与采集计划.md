## 当次分析内容（逆向分析完成，结论已确认）

### Cursor 数据目录实际结构

经过对 `%APPDATA%/Roaming/Cursor/` 和 `~/.cursor/` 两级目录的完整排查，确认数据存储在 **三个独立位置**：

```
%APPDATA%/Roaming/Cursor/
├── User/
│   ├── workspaceStorage/<hash>/
│   │   ├── state.vscdb          ← 工作区级 K-V 库
│   │   ├── workspace.json       ← 项目路径映射
│   │   └── anysphere.cursor-retrieval/  ← 检索索引（不直接用于采集）
│   └── globalStorage/
│       └── state.vscdb          ← 全局 K-V 库（跨项目 composer 元数据）

~/.cursor/
├── projects/<project-path-hash>/
│   └── agent-transcripts/<composerId>/
│       └── <composerId>.jsonl   ← 对话转录（核心内容）
└── ai-tracking/
    └── ai-code-tracking.db      ← AI 代码追踪 SQLite 数据库
```

### 三级数据源：agent-transcripts JSONL（对话转录，核心采集目标）

路径：`~/.cursor/projects/<project-hash>/agent-transcripts/<composerId>/<composerId>.jsonl`

格式与 Claude Code 的 `projects/*.jsonl` 类似：
```json
{"role": "user", "message": {"content": [{"type": "text", "text": "<user_query>\n用户输入\n</user_query>"}]}}
{"role": "assistant", "message": {"content": [{"type": "text", "text": "AI 回复"}, {"type": "tool-call", ...}, {"type": "tool-result", ...}]}}
```

- 每行一条 JSON 对象，`role` + `message.content[]`
- content 类型：`text`、`tool-call`、`tool-result`
- 用户消息包裹在 `<user_query>` XML 标签内
- 当前机器上有 2 个项目共 2 个 session（但 workspace vscdb 有 13+ session 元数据，说明历史 transcript 可能被裁剪）

### Cursor vs Trae 对照表（最终结论）

| 数据类别 | Cursor | Trae | 采集可行性 |
|---------|--------|------|:---:|
| 用户输入内容 | `*.jsonl` transcript | vscdb input-history | ✓ |
| 助手回复内容 | `*.jsonl` transcript | 云端（不可采集） | ✓ 重大优势 |
| 代码变更（diff） | 无 Git 快照 | Git 快照 tags | ✗ |
| 代码增删统计 | `composerData.totalLines*` | Git diff 计算 | ✓ 摘要级 |
| 工具调用记录 | `*.jsonl` tool-call/result | Git 快照 toolcall tags | ✓ |
| 会话元信息 | `composerData` (mode/name) | vscdb session map | ✓ |
| 项目路径 | workspace.json | workspace.json | ✓ |
| 模型信息 | `composerHeaders` | modelMap key | △ 待进一步确认 |
| Token 统计 | 无 | 无 | ✗ |
| 代码接受/拒绝 | 无显式标记 | Git 快照推断 | ✗ |
| 代码补全事件 | `aiService.generations` | 无 | ✓ 额外数据 |
