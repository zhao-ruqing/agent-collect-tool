# 数据采集链路修复与内容展示优化 — 2026-05-20 17:00

## 过往实现功能介绍

上次会话完成管理后台详情页、Diff 查看器、Agent 管理等多功能。但端到端联调发现数据无法写入 MySQL，且管理后台展示的是内容哈希而非用户实际输入，需要修复。

---

## 当次已实现功能

### 数据写入链路修复

- 后端 `process_batch` 新增 agent 自动注册：处理事件前先 `store::agent::insert()`，解决 FK 约束失败（agent_id 不在 agents 表）
- 事件重排序：Session/Conversation 优先处理，CodeEdit/Action 延后，解决子事件引用不存在的 session 行
- Axum 0.7 路由参数语法修正：`{session_id}` / `{agent_id}` → `:session_id` / `:agent_id`，修复 404 问题
- 请求体限制：`DefaultBodyLimit::max(50MB)` + `RequestDecompressionLayer`，解决 169 条事件超 2MB 默认限制
- Dashboard 日期类型修正：`DailyTrendItem.date` 从 `String` 改为 `chrono::NaiveDate`
- Agent 批量大小：`pop_batch(500)` → `pop_batch(50)`，避免单次请求过大

### Claude Code 解析器重写

- Agent `ConversationEvent` 结构体完全重写，匹配实际 JSONL 格式：嵌套 `message` 对象（role/content/model/usage）、`toolUseResult`（filePath/structuredPatch）
- 新增 `extract_content_text()` 工具函数，处理 content 的多种形态（纯文本 / 数组块 / thinking 块）
- `aggregate_conversation_events` 重写：从文件路径提取 session_id，从首个事件提取 cwd/git_branch，toolUseResult 生成 CodeEditRecord
- 修复会话数为 0 的问题（session_id 之前用空字符串）

### 原始内容展示

- 数据库：`messages` 表新增 `content TEXT` 列，存储会话原文
- 后端 Message 模型、store::message::insert/batch_insert 同步新增 content 字段（6 元组 → 7 元组）
- `process_conversation` 同时保存 `content_hash`（脱敏哈希，用于统计）和 `content`（原文，用于查看）
- 前端 ConversationDetail.vue：优先渲染 `<pre class="content-pre">{{ msg.content }}</pre>`，仅在 content 为空时回退显示哈希
- 清空旧数据后重跑 Agent 采集，验证：30 sessions / 1777 messages / 85 edits，API 返回完整原文

### 管理后台搜索功能修复

- 后端 `QueryParams` 新增 `keyword` 参数，`build_session_filter` 支持按 session_id 和 git_branch 模糊搜索（LIKE %kw%）
- 移除前端无效的"工具"/"模型"筛选（后端从未使用这两个字段筛选 sessions）
- 筛选栏重新布局：由拥挤的单行 inline form 改为 flex 三区布局（搜索框 | 日期范围 | 操作按钮），响应式折行
- 搜索框支持回车触发 + 前缀图标，日期选择器缩短 placeholder 文字
- 表格新增 Git 分支列，时间格式化改为 `toLocaleString('zh-CN')`
