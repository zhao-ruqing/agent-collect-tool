# Trae 采集器调试与 Bug 修复 — 2026-05-21 15:00

## 问题描述

系统中一条 Trae 信息都没有，需要进行端到端排查。

## 排查过程

### 1. 日志分析

以 `RUST_LOG=debug` 运行 agent，发现引擎仅注册了 `claude-code` 一个采集器——Trae 采集器从未被注册。

### 2. 配置排查

agent 二进制从 `target/debug/config.toml` 读取配置，该文件仅有 `tools = ["claude-code"]`，缺少 `"trae"`。主配置 `agent/config.toml` 虽有 `trae`，但 exe 目录优先级更高。

### 3. 数据格式验证

通过 Python 直接查询 Trae 的 `state.vscdb` SQLite 数据库，确认 AI 相关 key 全部存在且数据完整：

| Key | 状态 | 大小 |
|-----|:---:|------|
| `memento/icube-ai-agent-storage` | ✓ | 183 bytes |
| `icube_session_agent_map` | ✓ | 120 bytes |
| `icube-ai-agent-storage-input-history` | ✓ | 1253 bytes |
| `{userId}_ai-chat:sessionRelation:modelMap` | ✓ | 213 bytes |
| `currentAgentData_{userId}` | ✓ | 550 bytes |

将实际 JSON 与 parser 代码逐字段对比后，发现多处不匹配。

## 修复内容

### Bug 1: 配置缺失 — `target/debug/config.toml`

- **原因**：exe 目录中的配置模板缺少 `"trae"`
- **修复**：`tools = ["claude-code"]` → `["claude-code", "trae"]`
- **文件**：`agent/target/debug/config.toml`

### Bug 2: `vscdb.rs` — SQLite TEXT/BLOB 类型不匹配

sqlite 中 value 列实际为 **TEXT** 类型，但 `read_key()` 使用 `row.get::<Vec<u8>>()` 仅接受 BLOB。rusqlite 报错 `Invalid column type Text at index: 0` 导致所有 key 读取静默失败。

**修复** (`agent/src/collector/trae/vscdb.rs`):
```rust
// 改前: row.get(0) → Vec<u8>，TEXT 列报错
// 改后: row.get(0) → String，再 into_bytes()
let result: rusqlite::Result<String> = conn.query_row(...);
match result {
    Ok(s) => Some(s.into_bytes()),
    Err(e) => { log::debug!("读取 key '{}' 失败: {}", key, e); None }
}
```

### Bug 3: `parser.rs` — `parse_session_list` 未识别 `"list"` 键

Trae memento 数据格式为 `{"list": [...], "currentSessionId": "..."}`，代码只查找 `"sessions"` / `"value"` / `"data"`。

**修复**：添加 `v.get("list")` 为第一优先级的查找键。

### Bug 4: `parser.rs` — `SessionEntry.id` 字段名映射

JSON 字段为 `sessionId`，结构体为 `id`，无反序列化别名。

**修复**：`#[serde(alias = "sessionId")]`

### Bug 5: `parser.rs` — `model_map` 嵌套对象解析

Trae 格式：`{"sessionId": {"dev_builder": "model_name"}}`（内层键为 agent 类型）。代码只处理 `val.as_str()` 和 `val.get("model")`。

**修复**：内层对象取 `"model"` 键 → 无则取 `values().next()`

### Bug 6: `parser.rs` / `collector.rs` — 字段名不一致 + 关联逻辑

| 问题 | 修复 |
|------|------|
| `UserInputEntry.text` ↔ JSON `inputText` | `#[serde(alias = "inputText")]` |
| `UserInputEntry` 无 `sessionId` 字段 | 条目归入第一个会话 |
| `AgentConfig.tools` ↔ JSON `built_in_tool_list` | 支持 `[{"value":"name"}]` 格式 |
| `AgentConfig.type` 可能为 `unique_name` | 添加 fallback |
